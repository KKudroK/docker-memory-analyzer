# Inspect Files

## 용도

`inspect_files.InspectFiles`는 Linux 메모리 덤프에 기록된 **컨테이너 프로세스의 열린 파일 디스크립터(FD)와 관련 커널 메타데이터**를 조회하는 Volatility 3 2.28.0용 독립형 플러그인입니다. 어떤 프로세스가 어떤 객체를 열어 두었는지, 해당 객체가 프로세스와 호스트에서 어떤 경로로 연결되는지 확인하는 데 사용합니다.

`inspect_mount`가 컨테이너의 마운트 구성을 보여준다면, 이 플러그인은 **프로세스가 실제로 보유한 열린 FD**를 조사합니다. 다른 팀 플러그인에 의존하지 않으며, `inspect_mount.py`를 가져오거나 실행하지 않습니다.

### 분석 대상

FD는 프로세스가 열린 객체를 참조할 때 사용하는 번호입니다. 일반 파일뿐 아니라 디렉터리, 장치 파일, 파이프, 소켓, 익명 커널 객체도 FD의 대상이 될 수 있습니다. FD 번호는 프로세스 내부에서 사용하는 값이므로, 서로 다른 프로세스의 `FD 3`이 같은 파일을 의미하지는 않습니다.

플러그인은 FD별로 다음 정보를 제공합니다. 표시 항목은 선택한 보기에 따라 달라집니다.

- 소유 관계: 컨테이너 ID, 호스트 PID/TID, 프로세스 이름, FD 번호
- 객체 정보: 파일 유형, inode 번호, 링크 수, 열린 파일의 모드와 플래그
- 경로 정보: 프로세스 관점의 경로와 확인 가능한 호스트 경로
- 상태 정보: 이름 연결 상태, 경로 확인 상태, 메타데이터 판독 상태

기본 모드에서는 cgroup 소속, 런타임 조상 프로세스, 마운트 네임스페이스 정보를 근거로 컨테이너 관련 프로세스를 선별합니다. cgroup v1·v2 및 혼합 계층을 읽지만, 컨테이너 ID 추출에는 알려진 런타임의 cgroup 경로 패턴을 사용합니다. 따라서 모든 런타임과 사용자 지정 구성을 자동 식별하는 것은 아니며, 마운트 네임스페이스가 다르다는 이유만으로 컨테이너로 판정하지 않습니다. 자동 식별이 어려운 대상은 `--pids`로 호스트 PID(TGID)를 직접 지정할 수 있습니다.

### 메모리에서 정보를 수집하는 방식

프로세스와 스레드를 열거한 뒤, 각 태스크의 FD 테이블에서 열린 파일 객체를 따라갑니다.

```text
task_struct.files
  → files_struct.fdt
  → fdtable.fd[FD 번호]
  → struct file
```

`struct file`에서 열린 파일의 접근 모드와 플래그를 읽고, 연결된 `dentry`·`inode`·마운트 정보를 조사합니다. `dentry`는 이름과 부모 디렉터리 관계를, `inode`는 파일 유형·번호·링크 수 같은 메타데이터를 제공하며, 마운트 관계는 해당 객체의 경로를 구성하는 데 사용합니다.

스레드가 같은 FD 테이블을 공유하는 경우에는 동일 프로세스·동일 테이블·동일 루트 및 네임스페이스·동일 소속인 항목만 묶습니다. 상세 보기에서는 함께 묶인 TID를 표시합니다. 서로 다른 프로세스의 FD, 서로 다른 FD 번호, 별도 FD 테이블을 가진 스레드는 합치지 않습니다.

### 경로와 접근 모드의 의미

`Path`는 해당 태스크의 루트 디렉터리(`task.fs.root`)를 기준으로 확인한 경로입니다. 같은 컨테이너에 속하더라도 프로세스의 루트가 다르면 경로가 달라질 수 있습니다. 절대경로를 확인하지 못하고 이름만 읽은 경우에는 `name:파일명` 형태로 표시할 수 있습니다. 정상적인 FD가 프로세스의 현재 루트 밖을 가리키는 경우도 있으므로, 이름만 표시되었다고 해서 반드시 메모리 판독 실패를 의미하지는 않습니다.

`Host Path`는 호스트 기준 태스크인 `init_task`의 루트와 마운트 구성을 바탕으로 확인한 **호스트 측 마운트 별칭 경로**입니다. 단순히 컨테이너 경로의 접두어를 바꾸는 것이 아니라, 같은 파일시스템의 커널 객체와 마운트 연결을 따라 확인합니다. 경로가 여러 개 확인되면 각각 표시합니다. 다만 원래의 Docker 마운트 설정, 모든 하드링크 이름, overlay의 upper/lower 저장 경로를 복원하는 기능은 아닙니다. 경로가 확인되어도 해당 프로세스가 그 경로를 새로 열 수 있는 권한까지 입증하는 것은 아닙니다.

`Access`의 `R`, `W`, `RW`는 열린 파일 객체의 읽기·쓰기 모드이며, `PATH`는 `O_PATH` 방식의 경로 참조를 의미합니다. 이는 inode의 권한 비트와 다르며, 실제 읽기·쓰기 작업이 수행되었다는 증거도 아닙니다.

### 출력 상태의 해석

상세 보기의 상태 항목은 서로 다른 정보를 설명합니다. 위험도나 신뢰도 점수를 부여하는 항목은 아닙니다.

| 항목 | 의미 |
|---|---|
| `Name State` | 해당 이름의 연결 상태. `LINKED`, `UNLINKED`, `NAMELESS`, `ANONYMOUS` 등을 구분 |
| `Path Status` | 프로세스 기준 경로의 확인 상태. 전체 경로 확인, 이름만 확인(`NAME_ONLY`), 일부 판독 실패(`PARTIAL`) 등을 구분 |
| `Host Path Status` | 호스트 경로의 확인 상태. 한 개(`SINGLE`), 여러 개(`MULTIPLE`), 미확인(`UNRESOLVED`), 일부 판독 실패(`PARTIAL`) 등을 구분 |
| `Read Status` | 수집한 메타데이터에서 감지한 판독 누락이나 조사 범위 제한을 표시 |

`UNLINKED`는 FD가 참조하는 이름의 연결이 끊긴 상태를 의미합니다. 삭제 시각이나 행위자를 판정하는 값이 아니며, 다른 하드링크나 마운트 별칭까지 모두 사라졌다는 뜻도 아닙니다. 처음부터 이름 없이 생성된 임시 파일이나 익명 객체는 이 상태와 구분합니다.

`Read Status`의 `COMPLETE`는 조사한 메타데이터 범위에서 불완전성을 감지하지 않았다는 뜻입니다. 파일 내용이나 모든 증거가 복원되었다는 의미는 아닙니다. 기본 보기의 `State`에 붙는 `*`는 판독 누락 또는 조사 범위 제한이 있음을 나타내며, 상세 보기에서 사유를 확인할 수 있습니다.

예를 들어 `Path=name:null`, `Path Status=NAME_ONLY`, `Host Path=/dev/null`, `Host Path Status=SINGLE`, `Read Status=COMPLETE`인 결과가 나올 수 있습니다. 이는 프로세스 기준 절대경로 대신 이름만 확인했지만 호스트 경로는 확인했으며, 메타데이터 판독 누락은 감지하지 않았다는 뜻입니다. 이처럼 경로 확인 상태와 판독 상태를 별도로 해석해야 합니다.

### 출력 형식과 분석 범위

모든 보기는 **`Record / Field / Value` 세로 3열**로 출력됩니다. 같은 `Record` 번호는 FD 하나의 정보를 묶고, 컨테이너 ID·PID/TID·FD 번호도 각각 별도의 행으로 표시합니다. 여러 호스트 경로나 공유 TID는 해당 항목을 반복하여 표시합니다. `Record`는 현재 출력의 순번이며, 커널 객체의 주소나 실행 간 유지되는 식별자가 아닙니다. JSON·CSV 출력에도 같은 구조를 사용합니다.

이 플러그인의 분석 범위는 **덤프에서 확인 가능한 열린 FD와 그 메타데이터**입니다. 다음 작업은 수행하지 않습니다.

- 파일 내용 추출 또는 삭제된 파일 내용 복구
- 이미 닫힌 FD의 과거 이력과 실제 읽기·쓰기 행위 재구성
- FD 없이 메모리 매핑(VMA)에만 남아 있는 파일 조사
- 소켓의 통신 내용 분석 또는 악성 행위 판정

읽지 못한 FD 슬롯이나 `--max-fds` 제한으로 생략한 범위는 경고로 알립니다. 일부 제어문자·비UTF8 파일명에도 판독 제한이 있으므로, 결과가 없다는 이유만으로 열린 파일이나 이름 연결이 끊긴 파일이 없었다고 단정할 수 없습니다.

## 옵션

| 옵션 | 역할 |
|---|---|
| `--view files` | 기본 보기. 컨테이너 ID, PID/TID, FD 번호, 읽기·쓰기 모드, 이름 연결 상태, 경로 표시 |
| `--view hosts` | 확인된 호스트 경로와 경로 확인 상태 표시. 경로가 여러 개면 각각 출력 |
| `--view details` | 파일 유형, inode, 링크 수, 플래그, 판독 상태 등을 포함한 상세 정보 표시 |
| `--extended` | `--view details`와 동일. `--view files` 또는 `--view hosts`와 함께 사용 불가 |
| `--pids 1200 1300` | 지정한 호스트 PID(TGID)의 프로세스와 소속 스레드만 조회 |
| `--container abcdef012345` | 컨테이너 ID의 6~64자리 16진수 접두어로 선택. 다른 ID와 겹치면 더 길게 입력 |
| `--unlinked-only` | 이름 연결이 끊긴 상태인 `UNLINKED` FD만 표시. 삭제 행위·시점의 판정은 아님 |
| `--full-id` | 컨테이너 ID 전체 표시. 기본값은 충돌 없는 최소 12자리 축약이며 JSON·CSV에도 적용 |
| `--max-fds N` | FD 테이블마다 0~N-1 슬롯까지 조사. 기본 65,536, 허용 1~1,048,576. 제한 시 생략 경고 표시 |
| `-h` | 도움말 표시 |
